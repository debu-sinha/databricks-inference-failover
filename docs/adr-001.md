# ADR 001: Application-owned bounded fallback

Status: proposed reference implementation

## Decision

Use a small synchronous library with two destinations, no same-destination retry, explicit replay permission, refreshable token callbacks and a transport boundary. Use the documented Unified Responses request shape with a three-part model service. Keep model selection and provisioned capacity outside the client.

## Alternatives

A Gateway-managed fallback could centralize policy, but it does not by itself handle an unavailable workspace entry point. A general SDK retry layer adds useful features but can obscure the total attempt count when applications and Gateways retry too. A full distributed circuit breaker requires shared state, deployment choices and recovery thresholds that have not been agreed.

The small client makes each application-owned attempt visible. It adds no persistent health state. The application can extend the transport or add an independently reviewed routing strategy later.

## Consequences

The default fails closed. A 429 is never treated as permission to bypass an admission policy. Callers must explicitly approve the relevant status and destination before replay. A timeout does not prove the upstream request stopped, and an allowed replay can incur duplicate computation or charges. The library offers neither exactly-once behavior nor cross-workspace conversation state transfer.

The client supports text generation only. Streaming, tools, image inputs, prior-response continuation and background operations are outside this version. Regional placement, model availability, authentication setup and capacity must be established before production acceptance. Callback execution and operating-system DNS resolution are not forcibly interruptible by this synchronous library. Time budgets are checked before and after these boundaries.
